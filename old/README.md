# だるまさんがころんだ

プレイヤーは「だるま」。詠唱のテンポと我慢で、走ってくる子供たちを読み切る。

ビルド不要。HTMLを直接ブラウザで開けば動く(`file://` で動作するよう、モジュールではなく古典的な `<script>` で読み込んでいる)。

## ファイル

| ファイル | 役割 |
|---|---|
| `daruma-core.js` | **ゲームロジックの唯一の実装。** 1周の勝敗を決めるものは全部ここにある |
| `daruma-game.html` | 遊べるプロトタイプ。入力と描画だけ |
| `daruma-balance-lab.html` | パラメータ調整ラボ。数値をいじって方針別の勝率を測り、そのまま採用できる |
| `daruma-sim.js` | ヘッドレスのバッチシミュレータ。方針は持つがゲームロジックは持たない |
| `assets/` | 切り出し済みの画像素材。一覧は `assets/preview.html` |
| `tools/build_assets.py` | 元絵から `assets/` を作り直すスクリプト。普段は走らせなくていい |

3つのフロントエンドは以前それぞれがロジックの写しを持っていて、バランス変更を3箇所に手で反映する必要があった(そしてラボが調整対象のゲームから静かにズレた)。今は core だけが真実で、ここで測った数字は実際のゲームについての数字になる。

## 動かす

```sh
# ゲーム / ラボ
open daruma-game.html          # ブラウザで開くだけ

# シミュレータ
node daruma-sim.js
N=300 node daruma-sim.js                      # 1方針あたりの試合数
ONLY=smart_human,never_turn node daruma-sim.js # 一部の方針だけ
ROSTER=random node daruma-sim.js              # 毎試合10人から4人抽選(ゲーム本体と同じ挙動)
KIDS=10 node daruma-sim.js                    # 同時に走る人数
DARUMA_TYPE=oni node daruma-sim.js            # 全方針をそのだるまタイプで回す
```

`daruma-core.js` の `DEFAULTS` にあるノブはだいたい環境変数で上書きできる(`STAMINA_MAX`、`GOAL_TICKS`、`DRAIN_MAX`、`MISREAD` など。詳細は `daruma-sim.js` 冒頭)。

ラボで調整した値は localStorage 経由でゲームに渡る。**シムには渡らない**ので、残す価値のあるバランスは `DEFAULTS` に焼き込むこと。そうしないとシムとゲームが別のゲームを測ることになる。

## だるま側のルール

- 詠唱前に一時停止して、その周の **強気度**(低〜激)を決める。見送ったときの報酬と、振り向くときの気力コストが同時に上がる
- 詠唱中はテンポと「振り向く予約」をいつでも変えられる
- 詠唱を言い切った瞬間に判定。振り向けば**そのとき動いていた子だけ**を送還し、気力を払う
- 見送れば気力を得る。額は強気度どおりで、何周見送っても変わらない。かわりに**子供が振り向かないだるまを覚えている**ので、見送りが続くほど止まる気のない子が増える
- 気力が尽きると振り向けなくなり、それは子供に丸見えになる
- 子供が1人でもタッチしたら負け、制限時間(400tick = 40秒)を耐え切れば勝ち

勝利条件が「詠唱回数」ではなく時計なのは意図的。回数制だと速く詠むことが「1周を短くする」と「ゴールを近づける」の二重取りになり、一度も振り向かずに勝率100%になる。

## だるまのタイプ

開始前に選ぶ。強弱ではなく**別々の経済**にしてあるので、どれが最良かはその人の遊び方で変わる。

| タイプ | 得るもの | 失うもの |
|---|---|---|
| ふつう | — | — |
| 赤だるま | 気力の器が大きい | 見送りの実入りが細い |
| 鬼だるま | 振り向きが安い | 詠唱で押すのが高い |
| 攻めだるま | 詠唱が安い | 振り向きが高い |

**タイプは子供にも見えている。** 試合前に子供が持っている唯一の情報なので、「そういうだるまが出てきたら何を想定するか」という先入観(`expectTurn`)になる。そこから実績と重み付き平均を取るので、1周目は先入観がすべて、終盤には記録がほぼ塗り潰す。塗り替わる速さは子供ごとに違う(`skepticism`)。

これは評判が両刃になるということでもある。鬼だるまは怖がられるぶん子供が余計に止まるので、振り向いても空振りしやすく、そのかわり振り向かなくても止まってくれる。攻めだるまは逆に舐められる。

正直に書いておくと、タイプを分けているのは主にコスト構造のほうで、読まれることの寄与はそれより小さい。効きを強めたいなら `GAMBLE_THREAT_WEIGHT` がその蛇口。

`DARUMA_TYPE=oni node daruma-sim.js` で全方針をそのタイプで回せる。

## 子供のモデル

1周につき7つの判断でできている。①〜⑤が「止まれるか」、⑥⑦が「どう走るか」。

| | 判断 |
|---|---|
| ① | この周、そもそも止まる気があるか |
| ② | 自分の制動距離をどう見積もるか |
| ③ | 「そろそろ」に気づいてから足が動くまで |
| ④ | 疲れでブレーキがどれだけ鈍るか |
| ⑤ | どれだけギリギリまで粘るか |
| ⑥ | どの速さで走るか |
| ⑦ | 前に出るか、誰かの後ろにいるか |

パラメータは4層。

- **A 身体** — 最高速 / 加速 / ブレーキ / 持久力。見ていれば分かる。持久力は最高速と逆相関に置いてあり、タンク容量・燃費・回復力をまとめて決める
- **B 気質** — 大胆さ、自制心、反応、距離判断、疲労時の踏ん張り、**疲労の自覚**、**だるまへの疑い**。キャラ固定で、見えない
- **C 動機** — `MOTIVES` の4種(自分で決めたい / 捕まるのを気にしない / やる気なし / ふつう)を**試合ごとに抽選**。ロースターには書かれておらず、ラベルとしては表示されない
- **D だるまの読み** — 直近数周の振り向き実績を全員が共有し、疑い深さに応じて重みづける

C はロースターに書かれず、ラベルとしても表示されない。出るのは**走り方だけ** — やる気のない子は速度の上限が低く、気にしない子は先頭に居座って粘り幅を取らず、本気の子はゴールが近いほど押す。見ているうちに読めるようになるなら、それでいい。読めないことに価値があるわけではない。

捕まるのを気にしない子がいると、だるまは見送って気力を貯めにくくなる。狙ってやっているわけではなく、気にしていない結果そうなる。

同じ顔が試合ごとに違う役をやるので、キャラを覚えても動機は覚えられない。それと、4人以上の癖を同時に追うのは現実的ではない。結果としてだるま側は勘と気力管理が主になり、たまに1人の癖に気づく、くらいの解像度になる。

体力消費は速度に対して**指数的**(`RUN_DRAIN_EXPONENT`)。正比例だと同じ距離のコストが速度によらず一定になり、抑えて走る理由が消えて全員が全力で走ってしまう。指数にして初めてペース配分が判断になり、長距離型は終盤に加速し、短距離型は垂れる。

### ゲームでの使われ方

`daruma-game.html` は絵ありで起動する。設定画面のボタンで記号表示(元の絵文字と丸)に
戻せて、選択は localStorage に残る。**切り替えは `.app` に `art` が付くかどうかだけ**で、
両方のマークアップは常に DOM にあり、JS 側に描画の分岐は無い。HTMLだけ持ち出して
`assets/` が無い場所で開いた場合は、画像の `onerror` が拾って自動的に記号表示へ落ちる。

だるまの向きがそのまま合図になっている。詠唱中は子供に**背を向け**(右向き)、
振り向いた瞬間だけ**左を向く**。子供は左から来るので、向きを見れば見られているかが
分かる。子供の顔文字は消さずに残してあり、絵ありのときは「息切れ」「ダッシュ」
「捕まった」を示すバッジに降格している(平常時は出ない)。

**強気度は色・大きさ・脈の速さの3つを同時に振っている。** これはプレイヤーが毎周
賭ける額であり、子供が読んでいる情報そのものなので、盤面から一目で分かる必要がある。
透過PNGに縁のリングを付けると四角く出るため、絵の後ろに光そのもの(息づく `.aura` と
外へ抜ける `.aura-ring`)を置いた。色は**青→黄→橙→赤の一本道**。`--accent` と
`--orange` はほぼ同じ色なので隣り合う段に使うと「中」と「高」が見分けられない。
それでも段は4つあるので、字でも `強気度 高` と出している。

**子供の足は、止まれば止まる。** 走りの再生速度はその子自身の全力を1とした比
(`c.vel / c.maxSpeed`)で決めていて、止まった子はコマ送りも止まる。だるまが振り向いた
瞬間に誰が動いていたかは判定そのものなので、絵と判定がずれないことが要る。比で持って
いるのはバランスの数値を変えても絵の速さを調整し直さなくていいようにするため。

コマ送りは `background-size: 800% 100%` と `steps(8, jump-none)` で出している。
`background-position` の % は「要素幅」ではなく**「要素幅 − 画像幅」**に対する比なので、
8コマなら 0% が1コマ目、100% が8コマ目、間は 1/7 刻みになる。既定の `steps(8)` だと
12.5% 刻みになってどのコマにも乗らない(絵が消える)ので `jump-none` でないと駄目。

走る子供の元絵は `sozai/` に置いてある(1ファイル = 1人 × 8コマ、24MB)。こちらは
**最初からアルファが入っている**ので抜く仕事は無く、やっているのは「どこにコマが
あるか」を見つけて8コマを揃えることだけ。コマは等間隔に見えて実際は列の境をまたいで
いるので、4等分ではなくアルファの島を数えて拾っている。

元絵のうち1人だけ左を向いて描かれていたので、ビルドで反転して右向きに揃えている
(`RUN_FLIP`)。**反転はコマごとにかける。** シートごと反転すると各段の左右が
入れ替わってコマ順が逆になり、走りが巻き戻しになる。

子供の左向きは用意していない。ゴールは常に右で、`c.vel` が負にならない以上、子供が
左へ進むことはないため(捕まった子は歩いて戻らず `pos = 2` に転送される)。もし要る
なら、この絵柄は左右対称なので反転で作れる。新しく描き起こす必要はない。

だるまと `assets/kids/` の子供は元絵に背景が焼き込まれているので切り抜きが要る。
だるまは背景が横方向のグラデーションなので、左右の空き列から行ごとに背景を復元して
差分を取る。子供は背景が霧で色の差だけでは区別がつかないので、かわりに線画の密度を
見る(子供には黒い輪郭線が詰まっていて霧には無い)。どちらも最後に縁から背景の暗さを
差し引いてあるので、明るいテーマの上に置いても黒く縁取られない。

**`assets/kids/` が9人しかいないのは意図的ではなく限界。** 元絵が30人以上の重なった
群れで、隣の子の手足や床の靄を巻き込まずに抜けたのがこの9人だった。採用した子は
`tools/build_assets.py` の `KID_ANCHORS` に元絵の座標で名指ししてある。走る子供の
元絵が1人ずつ分かれているのは、この問題を元絵の側で解いたということ。

## 設計方針

**子供をできるだけ再現する。** 再現した結果つまらないゲームになったなら、それはしょうがない。コンセプトが「だるまさんがころんだ」である以上そこは動かせない。面白くするために外から機構(パワーアップ・特殊能力・アイテム)を持ち込まない。

ただし非対称で、再現の対象は**子供**。だるまはプレイヤーの席なので遊べることを優先する。

**数値ひとつで決まる設計にしない。** シムを回して「この数値を上げればいい」と即答が出るなら、どこかに歪みが出ている。振ったときの形で見る:

- 平ら → その要素は飾り
- 単調(上げるほど良い/悪い) → 端に張り付く
- 途中に山がある → 選択になっている

単調になるのは、その数値を上げた代償が同じ相手に返ってこないから。新しい要素を足すときは**代償の相手**をセットで決める。能力を持たせるなら、それを裏返せる口も同時に開ける(例: 子供にだるまの記憶を持たせるなら、テンポの知覚ラグで騙せるようにしておく)。

勝率は `node daruma-sim.js` を回せば出る。書き留めない — core をいじった時点で嘘になるので。
